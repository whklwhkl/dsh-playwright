# 配置与多会话机制 (Configuration & Sessions)

本文档汇总了 `playwright-browser` 插件的所有环境变量配置项，并详细说明了多会话隔离（Session Isolation）的实现原理。

---

## 一、环境变量配置参考

所有配置均通过环境变量传递给启动 DSH 的进程：

| 环境变量 | 默认值 | 作用说明 |
|---|---|---|
| `PW_LANG` | `zh` | 文档与工具输出语言。可选 `zh`（中文）或 `en`（英文）。影响工具参数描述、提示文案及 `playwright-browser-tips` skill。 |
| `PW_BROWSER_SCOPE` | `session` | 浏览器状态作用域。默认为 `session`（每个会话独立拥有浏览器/标签页）。设为 `shared` 可回退到 0.6 之前“全 profile 共享单一浏览器”的老行为。 |
| `PW_CHROMIUM_PATH` | 自动发现 | 自定义可执行浏览器路径（如指向系统已安装的 Google Chrome、Edge 或 Chromium），跳过 playwright 下载。 |
| `PW_HEADLESS` | `true` | 是否以无头模式运行。自建模式下设为 `false` 可弹出可见的浏览器窗口方便调试；挂载模式下该项无效。 |
| `PW_SHOT_DIR` | 插件目录下的 `shots/` | 页面截图（`browser_screenshot`）落盘目录。截图文件名会自动包含时间戳与会话标识。 |
| `PW_CDP_ENDPOINT` | 未设置 | 开启挂载模式：可设置为 `chrome`、`msedge` 等 channel 名称，或 `http://127.0.0.1:9222`，或 `auto`（先试 chrome，再试 9222）。多个端点可用逗号分隔作为回退。 |
| `PW_CDP_PAGE` | 未设置 | 挂载模式下，按 URL 或标题的**子串**匹配自动挑选要接手的默认标签页。 |
| `PW_CDP_TIMEOUT` | `90000` (90s) | 挂载建立连接的总预算时间（毫秒）。该超时时间同时也预留给用户在 Chrome 弹出的「允许远程调试」窗口中点击「允许」。若端口根本无人监听，插件会毫秒级快速失败，不会白等。 |
| `PW_RTT_TIMEOUT` | `1500` (1.5s) | 单次标签页轻量往返预算（毫秒），用于取标题、置前等操作。当目标标签页渲染进程卡死时，快速返回并将标签标为 `(无响应)`，防止挂死对话。 |

---

## 二、多会话隔离机制 (Session Isolation)

在 0.6.0 版本之前，整个 profile 内仅维护一份浏览器单例，当并行开启多个会话或运行子代理时，各智能体会抢占同一个窗口和标签页。

从 0.6.0 起，插件实现了**按会话隔离（Per-Session Browser）**的架构：

```
                    ┌──────────────────────────┐
                    │    DSH Agent Session     │
                    └─────────────┬────────────┘
                                  │
                  ┌───────────────┴───────────────┐
                  ▼                               ▼
        【自建实例模式】                     【CDP 挂载模式】
  每个会话独立 fork 浏览器窗口          所有会话共用用户 Chrome 实例
  ┌─────────────────────────┐         ┌─────────────────────────┐
  │ 会话 A: Chromium 进程 A │         │ 会话 A: 认领 Tab 1      │
  │ 会话 B: Chromium 进程 B │         │ 会话 B: 认领 Tab 2      │
  │ 子代理: Chromium 进程 C │         │ 子代理: 自动新建 Tab 3  │
  └─────────────────────────┘         └─────────────────────────┘
```

### 1. 核心行为特征
- **自建模式（Launch Mode）**：每个会话在首次调用 `browser_*` 时懒启动属于自己的 Chromium 实例。窗口、Cookie、存储、标签页完全独立。一个会话调用 `browser_close` 或对话结束时，只关闭自己的实例，不影响其他会话。
- **挂载模式（Attach Mode）**：共享用户的同一个 Chrome 浏览器，但每个会话驱动各自的标签页。插件在内存中记录标签页的占用状态（Claim 记账机制），避免会话间发生页面抢占。
- **生命周期绑定 Cordis Scope**：浏览器资源挂载在会话自身的生命周期钩子（`exec.agent.ctx.effect`）上。当会话、子代理销毁或 DSH 进程重载时，相关的浏览器实例或 CDP 连接自动安全清理。
- **同会话内串行排队**：同一会话内部可能存在并发的工具调用请求，插件在此处施加串行化队列（Serialization Queue），避免在选页、填表、跳转时产生竞态；而像 `browser_status` 这类只读状态查询则免排队直出。
- **可识别的会话标识**：会话标识统一提取自 DSH 会话 ID（去除 `session-` 前缀后的前 8 位 Hex，例如 `90b1706a`）。该标识会展示在 `browser_status` 查询结果中，并作为截图文件名的后缀（如 `shot-1710000000000-90b1706a.png`），避免并发截图文件互相覆盖。

### 2. 回退模式
若在某些特殊测试场景下希望恢复 0.6 之前全 profile 共享单例的行为，只需声明：
```bash
export PW_BROWSER_SCOPE=shared
```

### 3. 会话隔离机制自测验证
无需启动 DSH 完整环境，直接在本地仓库运行自测脚本，验证双会话隔离、挂载分页、抢占及销毁机制：
```bash
npm test
# 等价于：node scripts/test-session-isolation.mjs
```
该自测脚本会在真实环境中启动 Chromium，测试以下 4 项契约：
- PASS 1: 自建模式 —— 每会话独立启动、串行队列、生命周期销毁
- PASS 2: 挂载模式 —— 多会话标签页占用排他认领、接手与断开清理
- PASS 3: `PW_BROWSER_SCOPE=shared` 回退契约验证
- PASS 4: `browser_status` 会话可读标识与引导文案契约
